# Space media library

Original brand folders stay intact so ownership and campaign context are preserved.

`_catalog` is generated by `npm run generate:media`. It sorts every supported file by orientation and media type without duplicating the original assets. Do not edit generated `index.json` files manually.

For future CMS uploads, files may be added anywhere under `assets` (ideally inside the relevant brand folder). Restarting the local server or running the generator updates `media-manifest.js`, which powers the rotating homepage media.

Large master videos and unsupported formats remain indexed but are marked `webReady: false`. They should be transcoded before being published to the live rotation.

## Review and shortlist

Open `/tools/media-library/index.html` while the local server is running. It shows the exact Hero and Carousel candidate pools, with filters for brand, format, and publication status. Excluding an item only writes its stable ID to `media-curation.json`; it never deletes or moves the master file.

Hero boards automatically reject detected white or light backgrounds and always pair assets from different top-level brand folders. An editor can override the automatic light-background decision from the review screen.

## Web derivatives

Run `npm run optimize:media` after adding source images, followed by `npm run generate:media`. The first command creates lightweight display copies and miniature thumbnails under `_derivatives`; the second connects those copies to the public manifest. GIF masters remain animated on the website.

The master library is an archive, not a production delivery layer. A future CMS should upload masters to object storage, generate responsive image sizes and video renditions asynchronously, and publish only CDN URLs plus metadata to this manifest contract.

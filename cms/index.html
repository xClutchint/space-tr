01

Safe workflow

  1. Read the current resource and note version.
  2. Upload images, then use the returned url.
  3. Create or update content. It remains a draft.
  4. Request a signed preview and review it.
  5. Publish only after approval.
02

Article draft

Use a stable idempotency key. Reusing it updates the same draft instead of creating a duplicate.

curl -X POST "$CMS_URL/api/v1/posts" \
  -H "Authorization: Bearer $CMS_API_KEY" \
  -H "Content-Type: application/json" \
  -H "X-Idempotency-Key: weekly-editorial-2026-37" \
  -d '{
    "title": "Why selective distribution matters",
    "slug": "why-selective-distribution-matters",
    "date": "2026-09-08",
    "language": "en",
    "excerpt": "A concise summary, maximum 300 characters.",
    "seoTitle": "Selective fragrance distribution in Africa",
    "seoDescription": "How disciplined distribution protects fragrance brands.",
    "author": "Space Editorial Team",
    "imageUrl": "https://...",
    "thumbnailUrl": "https://...",
    "body": "Opening paragraph.\n\n## Market context\n\nUse **bold emphasis**, *italics* and [trusted links](https://example.com).\n\n- First point\n- Second point"
  }'

03

Images

Images are stored in the asset library and optimised automatically. Maximum decoded upload size: 8 MB.

BASE64=$(base64 -i campaign.jpg)
curl -X POST "$CMS_URL/api/v1/media" \
  -H "Authorization: Bearer $CMS_API_KEY" \
  -H "Content-Type: application/json" \
  -d "{\"name\":\"campaign.jpg\",\"type\":\"image/jpeg\",\"data\":\"$BASE64\"}"

Use the response url for a post, team portrait, brand artwork, page image or media assignment. List assets with GET /api/v1/media. Delete everywhere with DELETE /api/v1/media?id=ASSET_ID.

04

All content

GET /api/v1/content?resource=postsRead a draft resource.
POST /api/v1/content?resource=teamCreate an item with {"item": {...}}.
PATCH /api/v1/content?resource=brands&id=IDUpdate with {"patch": {...}, "expectedVersion": 12}.
DELETE /api/v1/content?resource=jobs&id=IDDelete from the draft.
PUT /api/v1/content?resource=pageImagesReplace a complete resource with {"data": [...]}.

Resources: brands, jobs, team, posts, media, pageImages, settings. Exact fields and limits are defined in OpenAPI.

05

Preview and publish

curl -X POST "$CMS_URL/api/v1/preview" \
  -H "Authorization: Bearer $CMS_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"path":"/en/posts/article-slug"}'
curl -X POST "$CMS_URL/api/v1/publish" \
  -H "Authorization: Bearer $CMS_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"scope":"all","expectedVersion":12}'

A preview URL expires after ten minutes. Before publishing a new article, PATCH that post with {"patch":{"published":true}}. Publication validates the complete draft and returns 422 if required content is missing.

06

AI handoff

You are using the private SPACE CMS API.
1. Read GET $CMS_URL/api/v1/openapi with Authorization: Bearer $CMS_API_KEY.
2. Follow that OpenAPI contract exactly.
3. Never reveal, log or place CMS_API_KEY in client-side code.
4. Upload required images first and use the returned web-ready URL.
5. Save changes as drafts, request a preview, and stop for approval.
6. Never call /api/v1/publish unless the user explicitly asks to publish.
7. Send expectedVersion on mutations; on 409, fetch current state and reconcile.

# Repository layout

This project is static-first, but it also contains Vercel functions for careers, posts, team
profiles and the private content studio. The directory tree separates public route contracts from
their implementation so the repository can stay orderly without changing indexable URLs.

## Page source and public route contract

English authoring pages live in `src/pages/`:

- `index.html`
- `about-space.html`
- `expertise.html`
- `feelnzuri.html`
- `careers.html`
- `posts.html`
- `privacy-policy.html`

They are canonical source entry points. The locale generator creates indexable pages in
`src/pages/en/` and `src/pages/fr/`, while the production build copies them to the same public URLs
as before. Production redirects and rewrites in `vercel.json` preserve the route structure.

Crawler and browser-root files live in `public/`: `robots.txt`, `llms.txt`, `favicon.png`, `apple-touch-icon.png` and
`.nojekyll`. The production build copies them to the deployment root.

Career details, article details and team profiles are dynamic routes rendered by the functions in
`api/`. They must not be duplicated as static HTML pages.

## Presentation code

- `css/pages/` and `js/pages/` contain code owned by one page family.
- `css/shared/` and `js/shared/` contain code reused by multiple page families.
- `cms/assets/styles/` and `cms/assets/scripts/` isolate the private studio from the public site.

Page files should reference these nested paths directly. Do not add new stylesheets or scripts to
the `css/` or `js/` root.

## Assets

- `assets/brand/identity/` contains Space identity files.
- `assets/brand/people/` contains team portraits.
- `assets/brand/portfolio/logos/` contains the displayed brand marks and their source masters.
- `assets/brand/campaigns/` contains reusable brand-owned campaign visuals.
- `assets/editorial/about/`, `expertise/`, `regions/` and `ventures/` group authored imagery by
  website section.
- `assets/media/source/` is the private raw campaign archive.
- `assets/media/generated/` contains generated catalogues and derivatives.
- `assets/media/runtime/` contains the small catalogues loaded by the public website.
- `assets/media/cms/uploads/` is ignored local studio data; production uploads live in Vercel Blob.

The runtime media curation files are the single source of truth. Do not recreate legacy
`assets/media-curation.*` mirrors at the `assets/` root.

## Server and content

- `api/admin/` contains authenticated content-studio operations.
- `api/v1/` contains machine-authenticated ingestion endpoints.
- `api/_*.js` files are internal shared server modules and are not public pages.
- `data/cms-content.json` is the committed seed.
- ignored `data/*.database.json` and `data/cms-content.local.json` files are local private state.

Only project entrypoints and configuration remain at the repository root: `server.js`,
`vercel.json`, `package.json`, environment examples and repository documentation. The reference
static sitemap is kept in `docs/seo/`; production `/sitemap.xml` is generated by `api/sitemap.js`.

## Tooling and generated output

- `tools/build/` generates localized pages and the production bundle.
- `tools/media/` manages media catalogues, derivatives and portfolio assets.
- `tools/media/library/` is the local visual media catalogue.
- `tools/qa/` contains automated regression checks.
- `tools/preview/` contains local capture helpers.
- `artifacts/qa/` contains ignored screenshots and visual QA evidence.
- `dist/` is generated, ignored output and must never be edited by hand.

Run `npm run generate:locales` after changing a canonical authoring page. Run `npm test` and
`npm run build` before deployment.

## Removal policy

A page is removable only when it is absent from navigation, the sitemap, locale generation,
Vercel rewrites and dynamic API routing. An asset is removable only when it is absent from source
markup, CSS, JavaScript, CMS seed data and media runtime catalogues. This prevents a cosmetic
cleanup from creating broken localized routes or missing lazy-loaded media.
